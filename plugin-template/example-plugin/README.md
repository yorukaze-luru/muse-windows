# プラグイン仕様（muse-plugin.json）

プラグインは「フォルダ」単位で扱います。フォルダの直下に `muse-plugin.json`（マニフェスト）を置くのが唯一の必須条件です。

## マニフェストの項目

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `id` | ○ | プラグインの一意な ID（半角英小文字とハイフン推奨） |
| `name` | ○ | プラグイン管理ページに出る名前 |
| `description` |  | ページに出る説明文 |
| `version` | ○ | バージョン（x.y.z 形式。新版判定に使います） |
| `exe` | ○ | フォルダ内にある実行ファイルの名前。起動・停止・開くの対象になります |
| `autostart` |  | `true` なら本体アプリの起動時に一緒に起動し、本体の終了時に一緒に終了します |
| `feed` |  | 更新フィード（yml）の URL。あれば新版チェックと自動アップデートが効きます |

## 動作

- 本体アプリは実行フォルダ直下の `plugins` フォルダを走査し、マニフェストのあるフォルダをプラグインとして一覧に出します
- 「起動／停止」は `exe` のプロセスを対象に行います。「開く」は起動と同じです（単一インスタンスのアプリを想定）
- 「アンインストール」はフォルダごと削除します

## 配布とアップデート

1. フォルダの中身を zip にします（**フォルダごとではなく、中身が zip の直下に来る**ように圧縮してください）
2. zip を GitHub Releases などに置きます
3. 更新フィードとして、次の内容の yml ファイルを zip と同じ場所に置きます

```yaml
version: 0.1.0
path: example-plugin-0.1.0.zip
```

4. マニフェストの `feed` に、その yml の URL を書きます

本体アプリはフィードを読んで `version` を比較し、新しければプラグイン管理ページに「アップデートあり」と出します。アップデートは zip を取得してフォルダへ展開し直す形で行われます。

## 注意

- プラグインは利用者の PC 上でそのまま実行されます。出所の分からないプラグインは入れないでください
- 本体アプリは Windows 用です。exe は Windows で動く実行ファイルを想定しています
